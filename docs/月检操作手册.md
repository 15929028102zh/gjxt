# 岗检系统 · 月检操作手册

**版本：V3.0（2026-09）**
**适用对象：检查（管理）部门人员、运行（受检）部门人员、系统管理员**
**取代旧版：《月检操作流程系统说明》V2.0（2026-08-11）**

---

## 一、流程总览

月检业务是一个"**建任务 → 录问题 → 提交公示 → 整改 → 复查闭环**"的完整流程：

```
① Web端：创建月检任务，设置月检时间段、公示时间段，发送通知
        ↓
② 移动端：检查部门人员选择任务，逐条录入发现的问题（保存后状态为"已确认/待提交"）
        ↓
③ Web端：检查部门在【月检提交】页面，将录入的问题单条或批量提交（状态变为"待整改"）
        ↓
④ 公示期：问题对外公示；公示期内如需修改，必须走"编辑审核"
        ↓
⑤ 公示期结束后：
   · 运行（受检）部门 → 移动端【确认整改】，填写整改建议/效果、上传整改照片（状态变为"已整改"）
   · 检查（管理）部门 → 移动端【确认复查】，填写复查结论、上传复查照片（状态变为"已复查"，问题闭环）
```

> **重要提醒（最容易出错的环节）：**
> 移动端录入保存成功 ≠ 问题进入整改流程。保存后记录处于"**已确认（待提交）**"状态，必须由检查部门在 Web 端【月检提交】页面统一提交后，才会进入"待整改"状态、开始公示和整改流程。

## 二、记录状态说明

| 状态 | 名称 | 含义 |
|---|---|---|
| 4 | 已确认（待提交） | 移动端刚录入保存的记录，等待检查部门在 Web 端提交 |
| 0 | 待整改 | 已提交，等待运行部门整改（公示期结束后可操作"确认整改"） |
| 1 | 已整改 | 运行部门已确认整改，等待检查部门复查 |
| 2 | 已复查 | 检查部门已确认复查，问题闭环 |
| 3 | 待审核 | 公示期内提交了编辑/删除申请，等待管理员在【待审核记录】中审批 |

## 三、任务阶段说明

每个任务根据"月检时间段"和"公示时间段"自动计算当前阶段，**不同阶段允许的操作不同**：

| 阶段 | 名称 | 时间范围 | 允许的关键操作 |
|---|---|---|---|
| 阶段1 | 录入期内 | 月检时间段之内 | 录入问题、提交、直接回退（无需审核） |
| 阶段2 | 公示前 | 录入结束 ~ 公示开始之前 | 提交、直接编辑/删除/回退（无需审核） |
| 阶段3 | 公示期内 | 公示时间段之内 | 修改/删除必须提交"编辑审核"；回退走编辑审核通道 |
| 阶段4 | 公示期后 | 公示结束时间之后 | **禁止编辑/删除/回退**；开放"确认整改""确认复查" |

> 记忆口诀：**公示前随便改、公示期改了要审、公示后只能整改复查。**

## 四、角色与终端分工

| 角色 | 使用终端 | 主要职责 |
|---|---|---|
| 检查（管理）部门人员 | 移动端 + Web端 | 移动端录入问题、确认复查；Web端建任务、发通知、提交记录、审核、导出 |
| 运行（受检）部门人员 | 移动端 | 查看本部门问题、确认整改；查看延迟整改提醒 |
| 系统管理员 | Web端 | 全部功能：任务管理、岗检标准维护、审核、导出、延迟整改督办 |

**终端分工原则：**
- **移动端**只负责三件事：**录入 → 整改 → 复查**（移动端不提供编辑、删除、撤回、审核入口）。
- **Web端**负责管理动作：**建任务、发通知、提交、编辑、删除、回退、审核、导出、延迟整改督办**。
- Web 端【月检提交】页面**仅检查（管理）部门可见**，运行部门登录后看不到该页面数据。

## 五、Web 端操作指南

Web 端左侧菜单【月检管理】下共有 6 个页面：

| 菜单 | 路径 | 开放对象 |
|---|---|---|
| 月检任务 | 月检管理 → 月检任务 | 月检管理员 |
| 月检记录录入 | 月检管理 → 月检记录录入 | 检查部门 / 管理员 |
| 月检提交 | 月检管理 → 月检提交 | 检查部门（运行部门不可见数据） |
| 岗检标准 | 月检管理 → 岗检标准 | 月检管理员 |
| 延迟整改 | 月检管理 → 延迟整改 | 全部相关人员 |
| 待审核记录 | 月检管理 → 待审核记录 | 有审核权限的管理员 |

### 5.1 月检任务（建任务、发通知）

**新增任务**，只需填写 4 项：

1. **任务名称**（必填）
2. **月检时间段**（必填）—— 决定"录入期"，只有在此时间段内才能在移动端录入问题
3. **公示时间段**（必填）—— 决定"公示期"，公示期内修改要走审核，公示期结束后才能整改/复查
4. **任务描述**（选填）

任务编号由系统自动生成（YJ + 日期），无需手填。

**操作按钮说明：**
- **通知**：向相关部门发送任务开始通知；发送后按钮置灰，防止重复发送。
- **批量通知**：勾选多个任务一次性发送通知。
- **查看**：任务详情中会显示"**当前阶段**"（未开始 / 录入期内 / 公示前 / 公示期内），可据此判断当前能做什么操作。
- **编辑 / 删除**：管理员可修改任务时间段或删除任务。

> 建议时间安排：月检时间段结束后紧接着开始公示期，公示期一般不少于整改所需时间；公示期结束时间一到，整改/复查入口自动开放。

### 5.2 月检提交（把录入的问题正式提交）

这是流程第③步的核心页面，**仅检查（管理）部门使用**：

1. 页面列出所有状态为"**已确认（待提交）**"的记录（即移动端已保存但尚未提交的记录）。
2. **单条提交**：点击某条记录后的"提交"按钮。
3. **批量提交**：勾选多条记录，点击"批量提交"。
4. 提交成功后，记录状态变为"**待整改**"，进入公示与整改流程。

**此页面也可以修改和删除记录，规则按阶段区分：**
- 公示期前（阶段1/2）：可直接编辑、直接删除。
- 公示期内（阶段3）：点击编辑/删除会弹出"**提交编辑审核**"窗口，需要填写修改说明（至少 5 个字），提交后记录变为"待审核"，等管理员审批。
- 公示期后（阶段4）：**不可编辑、不可删除**，系统会提示"已超过公示期，记录不可编辑或删除"。

### 5.3 月检记录录入（查看全部记录、确认整改/复查、回退）

检查部门和管理员使用的记录总览页：

- **查询筛选**：可按状态（待整改 / 已整改 / 已复查 / 待审核）、任务、部门等条件筛选。
- **新增**：也可在 Web 端直接新增记录（照片最多 5 张）。
- **导出**：月检管理员可将记录导出为 Excel。
- **行内操作按钮：**

| 按钮 | 可用条件 | 说明 |
|---|---|---|
| 查看 | 任何时候 | 查看记录详情 |
| 确认整改 | **仅公示期结束后（阶段4）** | 公示期结束前按钮置灰，鼠标悬停提示"公示期结束后才可确认整改" |
| 确认复查 | 记录状态为"已整改" | 检查部门复查确认 |
| 回退 / 编辑 | 阶段1、2、3 可见 | 见下方回退规则 |

**回退规则（重点）：**
- **阶段1 / 阶段2（公示期前）**：点击"回退"，确认后记录直接回到"已确认（待提交）"状态，可重新编辑或再次提交，**无需审核**。
- **阶段3（公示期内）**：按钮显示为"编辑"，点击后打开编辑表单，修改字段后点击"提交审核"，系统会记录**原值 → 新值的对比**，填写修改说明（至少 5 个字）后提交，记录进入"待审核"状态。
- **阶段4（公示期后）**：不可回退，系统提示"当前不在可回退时段"。

### 5.4 待审核记录（审核中心）

有审核权限的管理员在此页面处理公示期内提交的申请，分两个页签：

**① 编辑审核页签（常用）**
- 列出所有公示期内提交的编辑申请（状态为"待审核"）。
- 点击可查看**修改对比明细**：每个被修改的字段以"原值 → 新值"的形式展示（如：责任人、责任单位、发现位置、问题描述、性质界定、受检单位、整改期限、检查人等）。
- **通过**：修改的字段值**直接生效**，记录恢复到提交申请前的状态，继续原流程。
- **拒绝**：修改不生效，记录保持原样，回到申请前的状态。

**② 回退审核页签**
- 历史通道，用于处理特殊回退申请；通过审核后记录回到"待整改"状态。当前日常操作基本不使用此页签。

### 5.5 延迟整改（超期问题督办）

- 页面自动列出：**整改期限已过、但状态仍是"待整改"** 的记录，并显示超期天数。
- 管理员可以在此直接点击"确认整改"（针对状态为待整改的记录）或"确认复查"（针对已整改的记录），也可以点击"查看"了解详情后线下督办。
- 建议每周查看一次此页面，对超期未整改的部门进行催办。

### 5.6 岗检标准（标准库维护）

- 管理员维护岗检标准库（四级结构：专业类别 → 基本模块 → 责任要素 → 检查内容）。
- 标准按"**标准组**"划分（如：第一组-生产、第二组-辅助）。录入问题时，系统会根据所选**受检单位**自动匹配对应标准组的标准条目。
- 日常用户无需操作此页面，仅管理员维护。

## 六、移动端操作指南

### 6.1 月检主页

登录后进入月检主页，包含：

- **通知铃铛**：查看"系统通知"和"任务通知"两个页签，了解任务发布、审核结果等消息；支持一键全部已读。
- **问题录入按钮**：**仅检查（管理）部门人员和管理员可见**。点击后弹出"选择任务"窗口。
- **延迟整改按钮**：查看已超期未整改的问题。
- **统计卡片**（点击可跳转对应列表）：
  - 待整改问题 → 状态为"待整改"且整改期限未过的记录
  - 已整改问题 → 状态为"已整改"的记录
  - 已复查记录 → 状态为"已复查"的记录

### 6.2 录入问题（检查部门）

**步骤：**
1. 点击【问题录入】→ 在弹窗中选择任务（可按名称搜索）。若任务不在录入期内，系统会拦截并提示。
2. 进入录入表单，**按从上到下的顺序填写**：

| 序号 | 字段 | 填写说明 |
|---|---|---|
| 1 | 问题照片 | 最多 **3 张**，单张 ≤ 5MB，支持 JPG/PNG |
| 2 | 受检单位 | 选择被检查的运行部门。**选定后系统自动按该部门所属标准组加载下方的检查标准** |
| 3 | 发现位置 | 问题所在具体位置 |
| 4 | 问题描述 | 必填，最多 500 字 |
| 5 | 专业类别 | 四级级联选择第 1 级 |
| 6 | 基本模块 | 四级级联选择第 2 级 |
| 7 | 责任要素 | 四级级联选择第 3 级 |
| 8 | 检查内容 | 四级级联选择第 4 级；选定后**自动显示对应扣分值**（仅供查看，不影响录入） |
| 9 | 性质界定 | 选择问题性质 |
| 10 | 检查单位 | **自动锁定为当前用户所在管理部门，只读，不可修改** |
| 11 | 检查人 | 可多选 |
| 12 | 责任人 | 可多选 |
| 13 | 责任单位 | 可多选 |
| 14 | 整改期限 | 选择日期，运行部门须在此日期前完成整改 |

3. 点击保存。保存成功后记录状态为"**已确认（待提交）**"。

> **再次提醒：** 保存后请通知检查部门内勤在 Web 端【月检提交】页面统一提交，否则问题不会进入整改流程。
>
> **注意：** 只有任务的"月检时间段"内才能录入；录入期结束后系统会拒绝新增。移动端**不提供**对已保存记录的编辑和删除功能，如需修改请到 Web 端处理。

### 6.3 确认整改（运行部门）

**开放条件（两者必须同时满足，否则入口置灰并提示原因）：**
- 任务处于**公示期结束后**（阶段4）——公示期内提示"公示期尚未结束，整改入口暂不可用"；
- 当前用户为**运行（受检）部门**人员或管理员——检查部门用户提示"当前部门类型无整改权限"。

**操作步骤：**
1. 在月检主页点击"待整改问题"统计卡，或从记录列表找到状态为"待整改"的本部门问题。
2. 打开记录详情，点击【确认整改】。
3. 填写：
   - **整改建议**（必填）
   - **整改效果**（必填，最多 500 字）
   - **整改照片**（最多 3 张，单张 ≤ 5MB）
4. 提交后状态变为"**已整改**"，等待检查部门复查。

### 6.4 确认复查（检查部门）

**开放条件（两者必须同时满足）：**
- 任务处于**公示期结束后**（阶段4）；
- 当前用户为**检查（管理）部门**人员或管理员。

**操作步骤：**
1. 找到状态为"已整改"的记录，打开详情，点击【确认复查】。
2. 填写：
   - **复查建议**（必填）
   - **复查效果**（必填）
   - **复查照片**（最多 3 张，单张 ≤ 5MB）
   - 复查时如发现责任人/责任单位需要调整，可在此修改。
3. 提交后状态变为"**已复查**"，该问题正式闭环。

### 6.5 延迟整改提醒

- 移动端月检主页的【延迟整改】按钮，列出**整改期限已过但仍未整改**的本部门问题。
- 运行部门应优先处理此类问题；Web 端【延迟整改】页面同步展示，供管理员督办。

## 九、常见问题（FAQ）

**Q1：移动端保存了问题，为什么运行部门看不到"待整改"？**
A：保存后记录是"已确认（待提交）"状态，需要检查部门在 Web 端【月检管理 → 月检提交】中提交后才变成"待整改"。这是最常见的问题。

**Q2：为什么"确认整改"按钮是灰色的？**
A：两种可能：① 公示期还没结束（必须等公示时间段结束后才开放）；② 当前用户是检查部门人员（整改只能由运行部门或管理员操作）。

**Q3：为什么"确认复查"入口不可用？**
A：复查只能由**检查（管理）部门**人员或管理员操作，且同样必须等到公示期结束后。

**Q4：公示期内发现录错了怎么办？**
A：在 Web 端【月检提交】或【月检记录录入】页面对该记录点"编辑"，修改后填写修改说明（≥5 字）提交审核；管理员在【待审核记录】中看到"原值 → 新值"对比后审批。通过后修改直接生效，记录回到原状态；拒绝则维持原样。

**Q5：录入期内录错了怎么办？**
A：公示期开始之前（阶段1/2）可直接在 Web 端编辑、删除或"回退"，回退后记录回到"待提交"状态，改完再重新提交即可，无需审核。

**Q6：为什么移动端选完受检单位后，检查内容下拉的条目变了？**
A：这是正常现象。系统按受检单位所属的"标准组"（第一组-生产 / 第二组-辅助）自动过滤岗检标准，只显示该组适用的标准条目。

**Q7：整改期限过了还没整改会怎样？**
A：该记录会出现在移动端【延迟整改】和 Web 端【月检管理 → 延迟整改】页面，显示超期天数，管理员会督办。请尽快在移动端完成"确认整改"。

**Q8：任务通知发了，但有人说没收到？**
A：请对方查看移动端月检主页右上角的铃铛通知（含"系统通知"和"任务通知"两个页签）。通知按钮发送后会置灰，管理员可通过"批量通知"补发。

**Q9：运行部门登录 Web 端为什么看不到【月检提交】的数据？**
A：该页面仅对检查（管理）部门开放，属正常权限控制。运行部门的整改操作请在移动端完成。

**Q10：检查单位一栏为什么改不了？**
A：检查单位自动锁定为录入人所在的管理部门，为保证数据真实性不允许修改。

## 十、相对旧版手册（V2.0）的主要更新点

1. **岗检标准按"标准组"过滤**：录入时选定受检单位后，四级级联标准自动按该单位所属标准组（第一组/第二组）加载。
2. **移动端不再提供编辑入口**：移动端只保留"录入、整改、复查、查看"，编辑/删除/回退/审核全部集中在 Web 端。
3. **整改/复查双重管控**：必须"公示期结束后 + 部门类型匹配"（整改=运行部门、复查=检查部门）才能操作，Web 端"确认整改"同样限制在公示期结束后。
4. **公示期编辑审核升级**：审核中心展示字段级"原值 → 新值"对比；审核通过后修改直接生效并恢复到申请前状态；拒绝则回滚。
5. **月检提交页权限收紧**：仅检查（管理）部门可见，运行部门登录不再显示数据。
6. **任务表单简化**：建任务只需任务名称、月检时间段、公示时间段、任务描述 4 项，任务编号自动生成。
